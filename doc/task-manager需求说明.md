# 文档结构

任务管理入口文件使用 Org 格式，根节点固定为 `task manager`，下分 `工作任务` 和 `工作想法` 两个二级节点。

```org
* task manager

** 工作任务

*** TODO [#B] 任务标题
:PROPERTIES:
:工作类型: 研发任务
:相关产线:
:功能模块:
:创建时间:
:详情目录:
:详情文件:
:END:
:LOGBOOK:
CLOCK: [2026-06-16 Tue 09:30]--[2026-06-16 Tue 11:30] =>  2:00
:END:
- 任务描述：
- 工作总结：

** 工作想法

*** TODO [#B] 想法标题
:PROPERTIES:
:创建时间:
:详情目录:
:详情文件:
:END:
:LOGBOOK:
CLOCK: [2026-06-16 Tue 09:30]--[2026-06-16 Tue 11:30] =>  2:00
:END:
- 想法描述：
- 最终总结：
```

| 属性 | 说明 | 可选参数 |
| --- | --- | --- |
| 工作类型 | 工作任务分类 | 研发任务/支持任务 |
| 相关产线 | 任务关联产线 | 从外部产线列表中获取 |
| 功能模块 | 任务关联功能模块 | 从外部功能模块列表中获取 |
| 创建时间 | 任务或想法的创建时间 | 自动生成 |
| 详情目录 | 任务或想法工作目录 | 自动生成 |
| 详情文件 | 任务或想法详情文件路径 | 自动生成 |

优先级使用 Org 标准优先级语法，例如 `[#A]`、`[#B]`、`[#C]`。默认优先级为 `[#B]`。

## 工作任务详情文件

研发任务进入详情文件之后，默认创建基础模板。

```org
* 任务标题

** 背景信息

```

## 支持任务详情文件

支持任务是工作任务的一种，`工作类型` 固定为 `支持任务`。进入详情文件之后，默认创建支持任务模板。

```org
* 设备死机问题
:PROPERTIES:
:客户名称:
:软件版本:
:内核分支:
:内核版本:
:产品型号:
:供应商:
:END:

** 问题现象


```

## 工作想法详情文件

工作想法进入详情文件之后，默认创建想法模板。

```org
* 想法标题

** 想法描述

```


# 任务抽象

## 工作任务

工作任务用于记录明确需要推进的工作事项，必须包含任务标题、工作类型、相关产线、功能模块、创建时间和优先级。

工作任务可以按工作类型继续区分为：

- `研发任务`：以功能开发、代码调整、方案验证为主。
- `支持任务`：以问题支持、客户现场、版本排查为主。

## 工作想法

工作想法用于记录暂未转化为正式工作的想法，可以计时，也可以创建详情目录。

工作任务和工作想法都拥有独立工作目录。工作目录用于存放详情文件和相关过程材料，并且可以作为启动计时器的上下文。

## 状态流转

| 操作 | 原状态 | 新状态 | 行为说明 |
| --- | --- | --- | --- |
| 创建 | 无 | TODO | 创建节点并填写创建时间 |
| 开始 | TODO/DOING/PAUSED | DOING | 结束其它计时，当前任务或想法开始计时 |
| 暂停 | DOING | PAUSED | 停止当前计时 |
| 结束 | TODO/DOING/PAUSED | DONE | 停止计时并跳转到总结部分 |
| 取消 | TODO/DOING/PAUSED | CANCELLED | 停止计时并保留任务记录 |
| 重开 | DONE/CANCELLED | TODO | 不删除历史计时记录 |

如果当前存在其它 Org 任务正在计时，开始新任务时需要通过 Org clock 切换结束旧计时，并对当前任务调用 `org-clock-in`。

如果 Org 内部保留了计时状态但原 `CLOCK:` 起始行已不存在，开始任务，或暂停、结束正在计时的当前任务时需要自动清理失效计时状态，避免 `Clock start time is gone` 中断操作。

如果当前任务或想法已经是 `DOING` 但未在计时，开始操作需要继续为当前任务或想法创建新的计时记录；如果已经在计时，则保持当前计时。

开始操作既可以在 task-manager 入口文件中的任务或想法节点执行，也可以在该任务或想法对应的工作目录中执行。工作目录中启动计时器时，系统需要反查对应入口节点，并将 Org clock 记录写回入口节点，避免计时数据分散到详情文件中。


# 工作流程

- 创建任务或想法
- 开始任务或想法，开始任务或想法时自动打开详情文件
- 在工作目录中继续开始当前任务或想法计时
- 暂停任务或想法
- 结束任务或想法

## 创建任务

- 手动填写 `任务标题`。
- 选择优先级，默认 `[#B]`。
- 依次选择：
  - 工作类型
  - 相关产线
  - 功能模块
- `相关产线`、`功能模块` 从外部文件中获取。
- 自动填写 `创建时间`。
- 自动插入任务模板。
- 执行结束之后，光标跳转到 `任务描述：` 部分，由用户补充任务描述。

## 创建想法

- 手动填写 `想法标题`。
- 选择优先级，默认 `[#B]`。
- 自动填写 `创建时间`。
- 自动插入想法模板。
- 执行结束之后，光标跳转到 `想法描述：` 部分，由用户补充想法描述。

## 开始任务或想法

- 将当前任务或想法状态切换为 `DOING`。
- 开始当前任务或想法计时，并结束其它正在计时的任务。
- 如果当前任务或想法已经是 `DOING` 且没有正在计时，需要继续开始计时。
- 如果不存在详情目录，需要自动创建。
- 如果不存在详情文件，需要自动创建并写入对应模板。
- 自动进入详情文件。

详情目录名格式为：`2026.05.25-任务标题` 或 `2026.05.25-想法标题`。

详情文件位于详情目录下，文件名为：`任务标题.org` 或 `想法标题.org`。

## 工作目录计时

- 当前缓冲区文件位于某个任务或想法的 `详情目录` 内时，可以直接启动该任务或想法的计时器。
- 系统根据 task-manager 入口文件中的 `详情目录` 或 `详情文件` 属性反查唯一的任务或想法。
- 找到对应任务或想法之后，行为等同于在入口节点执行开始操作：停止其它计时、切换为 `DOING`、为入口节点创建 Org clock 记录。
- 计时记录必须写入入口文件中对应任务或想法的 `LOGBOOK`，统计报表只从入口文件收集计时数据。
- 从工作目录启动计时后，应保持当前工作目录或当前详情文件上下文，不强制跳回入口文件，也不重复打开详情文件。
- 工作目录中应提供跳回入口节点的能力，方便查看状态、属性和集中计时记录。
- 如果当前文件不属于任何已登记的 `详情目录` 或 `详情文件`，应提示无法定位任务或想法，不创建游离计时记录。

## 暂停任务或想法

- 仅允许暂停状态为 `DOING` 的任务或想法。
- 停止当前计时。
- 将状态切换为 `PAUSED`。

## 结束任务或想法

- 停止当前计时。
- 将状态切换为 `DONE`。
- 跳转到 `工作总结：` 或 `最终总结：` 部分。

## 打开详情文件

- 如果详情目录和详情文件已经存在，直接打开详情文件。
- 如果详情目录或详情文件不存在，按当前任务类型自动创建。
- 创建完成后同步写入 `详情目录` 和 `详情文件` 属性。


# 外部数据配置

`相关产线`、`功能模块`、`产品型号` 涉及公司内部信息，不直接保存到仓库中，由用户在本地单独提供。

建议使用纯文本文件维护外部列表，每行一个候选项，空行和以 `#` 开头的行忽略。

```text
# 示例
产线A
产线B
```

建议预留以下配置项：

| 配置项 | 说明 |
| --- | --- |
| `my/task-manager-product-line-file` | 产线列表文件，默认读取 `~/.emacs.d/local/相关产线.txt` |
| `my/task-manager-module-file` | 功能模块列表文件，默认读取 `~/.emacs.d/local/功能模块.txt` |
| `my/task-manager-product-model-file` | 产品型号列表文件 |

如果外部列表文件不存在，创建任务时应提示用户手动输入，不应中断整个创建流程。

如果外部列表文件存在且包含候选项，创建任务时应使用 Emacs 原生候选交互供用户选择。短候选列表使用 `read-multiple-choice` 单键选择，长候选列表回退到 `completing-read` 过滤选择。

内置候选项也使用相同方式，例如工作类型支持 `r` 选择 `研发任务`，`s` 选择 `支持任务`。

如果外部列表文件放在仓库目录下，但不需要通过 `stow` 安装到 `~/.emacs.d`，需要同步添加到 `.stow-local-ignore`。


# 文件与命名规则

- 入口文件为 task-manager 总文档，路径由 `path-type/index.el` 中的路径匹配规则决定。
- 详情目录创建在入口文件同级目录下，作为对应任务或想法的工作目录。
- 详情文件统一使用 `.org` 后缀。
- 文件名需要去除或替换 `/`、`\`、`:`、`*`、`?`、`"`、`<`、`>`、`|` 等不适合出现在文件名中的字符。
- 如果同一天存在同名任务或想法，目录名后追加序号，例如 `2026.05.25-任务标题-2`。
- 修改任务标题后，不自动重命名已经创建的详情目录和详情文件，避免破坏已有链接。


# 代码实现约束

建议实现以下交互命令。创建、暂停、结束、打开详情和统计等命令主要在 task-manager 入口文件中生效；`my/task-manager-start` 需要同时支持在入口文件及其登记的工作目录中生效，避免污染全局快捷键。

| 命令 | 说明 |
| --- | --- |
| `my/task-manager-create-task` | 创建工作任务 |
| `my/task-manager-create-idea` | 创建工作想法 |
| `my/task-manager-start` | 开始当前任务或想法 |
| `my/task-manager-pause` | 暂停当前任务或想法 |
| `my/task-manager-finish` | 结束当前任务或想法 |
| `my/task-manager-open-detail` | 打开或创建详情文件 |
| `my/task-manager-open-entry` | 从工作目录跳回对应入口节点 |
| `my/task-manager-report` | 查看工作时间统计 |

实现时需要遵守以下约束：

- 不在仓库中硬编码公司内部产线、模块、产品型号等敏感信息。
- 修改 Emacs Lisp 实现之后需要执行 `make format`。
- 如果新增脚本行为、加载路径、命令名称或配置入口，需要同步更新本文档。
- task-manager 相关配置通过 `path-type` 加载，优先只影响指定入口文件；工作目录计时只影响已由入口文件登记的工作目录。
- 工作目录中触发 `my/task-manager-start` 时，需要先定位对应入口文件和入口节点，再复用入口文件中的状态流转、计时和统计逻辑。
- 工作目录中触发 `my/task-manager-open-entry` 时，需要定位对应入口文件和入口节点，并跳转到该节点。


# 快捷键设置

快捷键建议使用局部 keymap，并统一使用 `C-c t` 前缀。

task-manager 入口文件使用完整快捷键：

| 快捷键 | 命令 | 说明 |
| --- | --- | --- |
| `C-c t c` | `my/task-manager-create-task` | 创建工作任务 |
| `C-c t i` | `my/task-manager-create-idea` | 创建工作想法 |
| `C-c t s` | `my/task-manager-start` | 开始当前任务或想法 |
| `C-c t p` | `my/task-manager-pause` | 暂停当前任务或想法 |
| `C-c t d` | `my/task-manager-finish` | 结束当前任务或想法 |
| `C-c t o` | `my/task-manager-open-detail` | 打开详情文件 |
| `C-c t e` | `my/task-manager-open-entry` | 跳回入口节点 |
| `C-c t r` | `my/task-manager-report` | 查看统计报表 |

已登记工作目录中的 Org 文件使用最小快捷键：

| 快捷键 | 命令 | 说明 |
| --- | --- | --- |
| `C-c t s` | `my/task-manager-start` | 开始或继续对应任务或想法计时 |
| `C-c t e` | `my/task-manager-open-entry` | 跳回 task-manager 入口节点 |

工作目录中的增强快捷键可以后续按使用频率扩展：

| 快捷键 | 命令 | 说明 |
| --- | --- | --- |
| `C-c t p` | `my/task-manager-pause` | 暂停对应任务或想法 |

| `C-c t r` | `my/task-manager-report` | 查看统计报表 |


# 统计与查询

工作时间统计基于 Org clock 数据生成。

需要支持以下统计维度：

- 按天统计任务耗时。
- 按周统计任务耗时。
- 按工作类型统计任务耗时。
- 按相关产线统计任务耗时。
- 按功能模块统计任务耗时。
- 按工作任务和工作想法分别统计耗时。

优先级排序基于 Org 优先级实现，默认排序顺序为 `[#A]`、`[#B]`、`[#C]`，同优先级内按创建时间排序。
