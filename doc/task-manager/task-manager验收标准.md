# task-manager 验收标准

本文档用于记录 task-manager 功能的验收标准，与 [task-manager需求说明](task-manager需求说明.md) 对应。

## 基础流程

- 创建工作任务后，应在 `工作任务` 节点下生成 `TODO` 任务，并自动填写创建时间、优先级和用户选择的属性。
- 创建工作想法后，应在 `工作想法` 节点下生成 `TODO` 想法，并自动填写创建时间和优先级。
- 开始任务或想法后，应停止其它计时、切换为 `DOING`、创建详情目录和 `.org` 详情文件，并打开详情文件。
- 对未计时的 `DOING` 任务或想法执行开始操作后，应继续创建新的计时记录。
- 暂停任务或想法后，应停止当前计时并切换为 `PAUSED`。
- 结束任务或想法后，应停止当前计时、切换为 `DONE`，并跳转到总结区域。

## 工作目录计时

- 在已登记详情目录中的详情文件执行开始操作后，应定位到对应任务或想法，停止其它计时，并将对应入口节点切换为 `DOING`。
- 从详情目录启动计时后，新的 `CLOCK:` 记录应写入入口文件中对应任务或想法的 `LOGBOOK`，不应写入详情文件形成分散统计。
- 从详情目录启动计时后，应保持当前详情文件或工作目录上下文，不强制跳回 task-manager 入口文件。
- 在未登记为任何 `详情目录` 或 `详情文件` 的文件中执行开始操作时，应提示无法定位任务或想法，并且不创建计时记录。
- 从详情目录启动的计时记录，应能被 `my/task-manager-report` 统计到对应工作或想法中。

## 快捷键

- task-manager 入口文件应提供完整局部快捷键：创建任务、创建想法、开始、暂停、结束、打开详情、跳回入口节点和查看报表。
- 已登记工作目录中的 Org 文件至少应提供 `C-c t s` 启动计时和 `C-c t e` 跳回入口节点。
- 在工作目录中执行 `C-c t e` 后，应跳转到 task-manager 入口文件中的对应任务或想法节点。
- 工作目录中的增强快捷键 `C-c t p`、`C-c t d`、`C-c t r` 可以后续实现；实现后行为应与入口节点对应命令保持一致。

## 数据与文件

- 外部列表文件缺失时，创建流程仍可通过手动输入继续完成。
- 详情目录或详情文件已经存在时，不重复创建，也不覆盖用户已有内容。
